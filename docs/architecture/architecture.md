# Azure FinOps Cost Governance — Architecture

## 1. Purpose

This project demonstrates cloud cost governance through secure cost-export
storage, automated validation, cost allocation, anomaly detection, budget
notifications, and observability.

The architecture separates real Azure billing data from the local synthetic
observability demonstration.

The local observability stack runs through Docker Compose. Prometheus scrapes
the exporter, and Grafana displays sample-window costs, project and service
breakdowns, daily costs, and a synthetic anomaly indicator.

This dashboard is deliberately separate from the actual Azure billing path.
Its dataset is synthetic; its $10 budget reference is illustrative and is
not a spending cap or a measure of actual Azure month-to-date spending.
5. Security and governance controls
- Keep actual billing exports and credentials out of Git.
- Use Microsoft Entra ID authentication for authorized Azure access.
- Use GitHub OIDC federation instead of long-lived Azure credentials.
- Keep the Blob Storage container private and shared-key access disabled.
- Preserve currency boundaries and make attribution gaps visible.
- Treat budget thresholds as notifications, not hard spending limits.
- Do not publish actual billing totals or claim savings without evidence.
6. Current scope and limitations
Implemented:
- Azure Cost Management export and private Blob Storage configuration.
- Terraform-managed development storage infrastructure.
- Python export validation, cost allocation, and anomaly detection.
- GitHub Actions automated validation.
- Azure budget configuration and notification thresholds.
- Local Prometheus and Grafana demonstration using synthetic data.
Not yet implemented as end-to-end production capabilities:
- Direct integration of actual Azure cost records into Grafana.
- Cost-per-request metrics.
- OpenCost-based Kubernetes allocation and rightsizing.
- Automated idle-resource remediation and shutdown workflows.
